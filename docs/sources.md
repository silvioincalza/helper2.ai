# Source registry

What Helper2.ai actually queries. Live view: `GET /api/v1/sources` and the Sources page.
Evidence for every term/limit: [research/sources-and-costs.md](research/sources-and-costs.md).

| id | Name | Mode | Endpoint | Auth | Limits | Terms / attribution | Dates provided |
|---|---|---|---|---|---|---|---|
| `github` | GitHub | LIVE | `GET /search/repositories` | optional `H2_GITHUB_TOKEN` | 10/min unauth, 30/min token | GitHub ToS; no token pooling | created_at → published; pushed_at → updated |
| `hf-models` | Hugging Face models | LIVE | `GET /api/models?search=` | optional `H2_HF_TOKEN` | 500/5 min anon | HF ToS (silent on metadata reuse → UNKNOWN, link back to model) | createdAt, lastModified |
| `hf-spaces` | Hugging Face Spaces | LIVE | `GET /api/spaces?search=` | optional `H2_HF_TOKEN` | same | same | createdAt; lastModified often absent → unknown |
| `npm` | npm registry | LIVE | `GET /-/v1/search?text=` | none | unpublished; be reasonable | npm Open-Source Terms: API OK, no website crawling, no reuse of security data | `date` (latest publish) → updated; created unknown, so npm results never answer "born in a period" (migration V2 cleared older rows) |
| `arxiv` | arXiv | LIVE (+6 h cache) | `GET /api/query` (Atom), AI categories only (cs.AI, cs.CL, cs.LG, cs.CV, cs.MA, cs.IR, stat.ML) | none | 1 request / 3 s (adapter self-throttles → RATE_LIMITED) | Metadata CC0; must not imply endorsement; acknowledgement shown | published, updated |
| `tavily` | Tavily web search | LIVE (+cache), **only with `H2_TAVILY_API_KEY`** | `POST /search` topic `news` | Bearer key | 1 credit / basic search; free tier 1,000 credits/month | Terms read 2026-10-25 ([tavily.com/terms](https://tavily.com/terms), last updated 4 May 2026): use "solely for Customer's internal business purposes" (§2, §3.2); no building a "competitive product or service" (§3.2(v)); Output is not part of "Services" (§1.7), so caching it is not restricted; no attribution clause. **Public redisplay is not clearly covered: get written OK from Tavily before launch** (see research doc §8) | `published_date` (Tavily's estimate, null → unknown); event dates never inferred |
| `course-scout` | Course and certification pages | REVIEW ONLY (Scout, every 7 days), **only with `H2_TAVILY_API_KEY`** | `POST /search` topic `general`, one query per platform with `include_domains` (coursera.org, oreilly.com, edx.org, udemy.com, deeplearning.ai, huggingface.co/learn, cloud.google.com/learn, aws.amazon.com/certification, learn.microsoft.com/en-us/credentials, nvidia.com), `start_date` = previous pass. | `hf-trending` | Hugging Face trending models | INDEXED (Scout, every 1 day) | `GET /api/models?sort=trendingScore&direction=-1&limit=100`, kept only with ≥ 20 likes | optional `H2_HF_TOKEN` | 1 request / pass | same as `hf-models` | createdAt |
| `tavily-scout` | Tavily discovery queries | INDEXED (Scout, every 5 days), **only with `H2_TAVILY_API_KEY`** | `POST /search` topic `news`, 7 fixed queries (4 general, 3 on new models by provider: OpenAI/Anthropic/Google, xAI/Meta/Mistral, NVIDIA/DeepSeek/Qwen), `start_date` = previous pass | Bearer key | 1 credit / query → ~42 credits/month | same as `tavily` | `published_date` (Tavily's estimate) |
| `github-awesome` | GitHub awesome lists (AI) | INDEXED (Scout, pass every 1 day, ≤ 200 entries per run, ≤ 1,000 per pass), **only with `H2_GITHUB_TOKEN`** (GraphQL rejects anonymous calls) | `GET /search/repositories` by topic pair (6 queries, ≥ 1,000 stars, name must contain "awesome", top 10 lists) → `GET /repos/{list}/readme` (raw) → `POST /graphql` 50 repos per call. Entries kept with ≥ 50 stars, not archived, not a fork, and judged AI by the fast model (`helper2.llm.fast-model`, Nemotron 3 Nano; keyword rules if no model or no answer) | token: a fine-grained PAT with public read-only access is enough | per pass ~6 search + 10 README + 20 GraphQL calls; Nano ~0.5 s/entry, 25 per call | GitHub ToS. The lists are used only as links: no list text is stored; descriptions, license, stars and dates come from the GitHub API. **The type is the model's choice** (no per-field origin on `type` yet) | createdAt → published; pushedAt → updated |
| `hf-provider-orgs` | Hugging Face provider organizations | INDEXED (Scout, every 1 day) | `GET /api/models?author={org}&sort=createdAt&direction=-1&limit=20` for meta-llama, nvidia, mistralai, deepseek-ai, Qwen, google, openai, xai-org; the org is added as a tag | optional `H2_HF_TOKEN` | 8 requests / pass | same as `hf-models` | createdAt |
| `ai-deadlines` | AI conference dates (huggingface/ai-deadlines) | INDEXED (Scout, every 1 day) | `GET /repos/huggingface/ai-deadlines/contents/src/data/conferences` → each raw YAML file; one record per conference, rolled to its next edition that has not ended | optional `H2_GITHUB_TOKEN` (contents API: 60/h anon) | 1 API call + ~70 raw files / pass | MIT License; link back to the repository and each conference's own site | `start`, `end` → event days (DAY precision); no publication date |
| `mcp-registry` | Official MCP Registry | INDEXED (Scout) | `GET /v0.1/servers?updated_since&cursor` | none | unpublished; sync hourly | CC0; "This data comes from the Official MCP Registry"; preview API, data may reset | publishedAt, updatedAt |
| `helper2-index` | Helper2 index | INDEXED | PostgreSQL FTS | — | — | own data | relays original attribution |
| `curated` | Helper2 curated list | CURATED | PostgreSQL | — | — | editorial; no publication dates or prices asserted. Industry and community events (hackathons, meetups, talks, workshops) carry the days stated on each event's own site, with that excerpt as evidence, and the format (online, in person) only when the page states it | event days only (industry events) |
| `demo-*` | Demo sources | DEMO | in-process fixtures | — | — | **profile `demo` only** | fixture |

**Every source call** ([ADR 0006](adr/0006-outbound-http.md)): a token goes only to the configured host (no redirect
to another host while `Authorization` is set); a body is read up to 2 MB (awesome-list READMEs 5 MB), past that the
source is `FAILED` ("response too large"); a malformed item is dropped and counted in
`helper2.source.items.dropped{source,reason}` while the other items are kept.

**Not connected (and why):** Hacker News via Algolia (no readable terms of use found), PyPI (no search API), Product Hunt (API forbids commercial use),
There's An AI For That (terms not obtainable), paid web-search APIs other than Tavily.

**Adding a source:** verify docs/terms/limits/costs → add a row here and in the research doc →
implement `SearchSource` and/or `Collector` → boundary tests with recorded fixtures → a `@Tag("live")` smoke test.
