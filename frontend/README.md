# Helper2.ai frontend

Vite + React 19 + TypeScript 6 (strict) + React Router 8 (data mode, `createBrowserRouter`), SPA.
Hand-written CSS with design tokens (`src/styles/tokens.css`). i18n: i18next (English).

## Requirements
Node 26 (`.nvmrc`).

## Scripts
| script | what |
|---|---|
| `npm run gen:api` | `openapi-typescript`: `../api/public.yaml -> src/api/schema.ts` and `../api/admin.yaml -> src/api/admin-schema.ts`, types and enum value arrays (git-ignored, regenerated by `prebuild`, `pretest`, `pretypecheck`, `prelint`, `preknip`) |
| `npm run dev` | Vite on :5173, proxies `/api`, `/oauth2`, `/login`, `/logout` to `http://localhost:8080` |
| `npm run dev:admin` | the back office web app (ADR 0043) on :5174, at `/admin`, same proxy |
| `npm run typecheck` / `lint` / `test` / `build` | tsc, ESLint flat config, Vitest (jsdom), tsc + two vite builds: the public app to `dist/`, the back office web app (`admin.html`, `vite.admin.config.ts`) to `dist-admin/` under `/admin/` |
| `npm run check:bundle` | after `build`: fails when the JavaScript of a first visit passes 250 KiB gzip, or a page chunk 30 KiB (`scripts/check-bundle.mjs`; run in CI) |
| `npm run knip` | dead code, strict (`knip.json`, ADR 0047): unused files, exports, types, members and dependencies in the whole project, then the app code's files and dependencies in production mode; run in CI |

## Structure
One folder per feature, in the words of the backend's contexts; the shared parts beside them.
```
src/features   one folder per feature: search (box, results, filters), guide, home (radar, New this week, Coming up),
               resource, saved, sources, news, events, setup, account (sign-in, account page), pages (Mission, Privacy,
               Terms), monetisation (support, ads, the analytics question)
src/shell      the frame of every public page: Layout (header, footer), RouteError, NotFoundPage, Robots
src/ui         the shared kit of the design system (ADR 0040): StatePanel, StatusPill, ProofQuote, SourceTiles, PicksBar,
               Icon, Logo, Badges, Term, term.css, ui.css, listing.css
src/admin      the back office web app: main.tsx (entry), routes.tsx, AdminShell.tsx (skip link, main) and its pages;
               own admin.css
src/api        schema.ts and admin-schema.ts (generated), types.ts (aliases), client.ts (typed fetch, CSRF, problem+json, guide stream)
src/lib        searchState.ts (URL <-> state, guide refinement, RESULTS_PATH, resourcePath: every resource link encodes the id), selection.ts (selected result, picks), breakpoints.ts, countdown.ts, locateQuote.ts, format.ts, bookmarks.ts (localStorage, try/catch)
src/context    MeContext (GET /me), BookmarksContext (local, merged once to server on sign-in), MonetisationContext (GET /site)
src/hooks      useApi (keyed fetch with AbortController, recent-answers cache, ADR 0039), useGuideStream (guide SSE for the URL's question), useRetry (Try again keeps focus on a heading), useTitle
src/styles     tokens.css (from docs/design/system/tokens.json, checked by tokens.test.ts), app.css (the shared controls), shell.css (header, footer, page column)
src/i18n       index.ts + locales/en.json, en.legal.json (Privacy and Terms, loaded by their pages),
               en.admin.json (the back office's copy, never in the public bundle)
src/test       fixtures, fetch mock, render helper, axe helper, queries
```

## Decisions
- **All search state lives in URL params** (`q, view, sort, page, updatedAfter, openSource, type, source, license, pricing, platform, useCase, techLevel, audience`), and the guide's in `ask, clar, drop`. A search change keeps the question and its refinement; a new question starts without one.
- Stale searches are canceled: `useApi` aborts the previous request when the key changes.
- Honesty: every search shows a collapsible source-status summary + table (outcome, mode, served-from, latency, checkedAt, cachedAt); partial banner; stale-cache badges; `DateFact` UNKNOWN renders "Unknown", CONFLICTING lists alternatives with source ids; popularity is always "value metric · source · as of date", never combined. Status is always icon + text.
- Relationships: only `VERIFIED` appear as confirmed; `UNVERIFIED`/`CONFLICTING` go to "Unverified candidates"; `REJECTED` are not shown.
- Glossary terms are buttons with `aria-expanded` revealing an inline definition.
- Unknown facet bucket: facet value `unknown` is labeled "Unknown". For enum-typed filters (`pricing`, `techLevel`, `audience`, `type`) it is sent as `UNKNOWN` (the contract's enum spelling); for `license`, `platform`, `useCase`, `source` as `unknown`.
- Versions are pinned exactly and current as of 2026-10-24, except: TypeScript **6.0.3** not 7 (typescript-eslint needs <6.1; `overrides` lets openapi-typescript use it, `npm ci` verified) and ESLint **9.39.5** not 10 (eslint-plugin-jsx-a11y supports ≤9).
- UI language: English only, with no language choice. The copy stays in `src/i18n/locales/` (`en.json`, and `en.legal.json` for Privacy and Terms). A second language comes with its own change: the locale file, a language choice, and its storage key on the Privacy page.
- Tests mock `fetch` directly (`src/test/mockApi.ts`), not msw.
